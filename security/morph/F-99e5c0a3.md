# PATCH 64-bit unsigned offset wrap bypasses bound check → out-of-bounds memcpy into slot metadata/adjacent memory (CWE-190/787)

**Finding** `F-99e5c0a3` · **Severity** high · **Confidence** proven

> Opened by morph — a vulnerability reproduced in the binary, with the reproducer and a proposed remediation. Review and adapt before merging.

## Impact
Attacker-controlled out-of-bounds write into arena slot metadata and adjacent slot buffers. Directly forges a slot's active/type/16-bit generation fields, enabling type confusion (slot type 'B' vs 'J'), resurrection of dropped slots, and corruption of neighbouring slots' contents — a memory-corruption primitive in a hardened-parsing server. The wrapped offset also lets the write land before the state base (idx=0), into dispatcher stack locals.

## Attack path
1) Client sends `BUF <hex>` to allocate a slot; reply leaks handle (type/idx/gen/epoch packed, see OK buf=%016lx). 2) Send `PATCH <handle> <offset> <hexdata>`. The offset is parsed by strtoul (base 0) at 0x32e5 into r13, unbounded 64-bit. The handler's only guard is `lea rax,[r13+r12]` (0x3812) / `cmp rax,0x90` (0x3817) / `ja` (0x381d), where r12 is the hex-decoded length (<=0x90). This 64-bit add wraps. 3) Supply offset=2^64-n; the sum becomes small and passes. 4) memcpy at 0x383f with dst = state + idx*0x98 + 8 + offset (mod 2^64) (0x3823-0x383c), src = decoded hex buffer (r15), n = r12. Written bytes land up to 0x90 bytes before the intended inline slot buffer, i.e. on the target slot's header (active/type/generation at slot+0..+5) and the previous slot's data buffer. Dynamic proof: PATCH handle b6a77b8eb4fb3a3d 18446744073709551608 0000000000000000 returned `OK patched=8`; the following VIEW/DROP for that handle then returned ERR view / ERR handle because slot+0's active byte had been overwritten.

## Proposed remediation
Validate offset and length separately without a wrapping add: reject if offset > 0x90, then reject if length > 0x90 - offset (or `if (offset + length > 0x90 || offset > 0x90)` using unsigned checks against a per-slot stored size). Track the allocated size per slot (BUF currently stores none) and bound PATCH against that.
